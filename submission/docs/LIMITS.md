# LIMITS — 适用边界与已知失效模式

## 1. 适用范围

- **任务**：方法与实验章节、实验设置、参数对齐、复现清单、限制条件披露。
- **材料形态**：yaml / json / toml / ini / log / sh / py / md / csv / tex 文本。
- **语言**：中英文材料与草稿；模板与套话词表以中文为主，英文限制条件可用 `if/when` 触发词。
- **规模**：单案例材料通常在几十个文件以内；引擎按文件全量扫描，不做增量。

## 2. 明确不做

- 不生成实验数据、指标、结论或引用；材料没有的事实保持缺失。
- 不判断材料本身是否正确（配置写错、日志造假不在校验范围）。
- 不渲染 PDF / TeX / Office；只产出 Markdown（及可继续编辑的 LaTeX 片段）。
- 不做 PDF 版面还原；扫描件需先 OCR，OCR 噪声会进入台账并可能产生 `unverified`。

## 3. 已知失效模式

| 场景 | 表现 | 缓解 |
|-|-|-|
| 配置是自由格式文本、无 `key: value` | 抽取不到参数 | 由模型提议，必须带 locator + quote，引擎回读校验 |
| 同一参数在多个实验中取值不同 | `conflict`，正文无法渲染 | 按作用对象拆分键（`train_` / `val_` / `test_`），仍冲突则交作者 |
| 单位缺失 | `params.unit` 记为 gap | 正文不写单位或写 `{{?unit}}`，不补造 |
| 数字恰好在白名单语境（如 "Table 2"） | 放行 | 白名单只覆盖编号，不覆盖实测值 |
| 草稿把数字写进代码块 | 仍按未绑定处理 | 代码块内的命令也用槽位 |
| OCR 把 `1` 识别成 `l` | 抽取失败或值错误 | 标记 OCR 来源，低置信度入追问 |
| 作者用 `--allow` 放行大量数字 | 防火墙形同虚设 | `allowlist.txt` 需逐行注明原因，评审可查 |
| 材料里根本没有 seed / commit | `[MISSING]` | 这是正确行为，不得补造 |

## 4. 资源与合规

- 文本文件 ≤ 50 个、单件 ≤ 500KB、合计 ≤ 2MB、无符号链接。
- `submission/` 内所有文件必须带扩展名；`.gitignore`、`LICENSE` 等无后缀名文件只放在仓库根。
- `check` 会生成 `pack_report.json` 做自检；`tests/run_tests.py::test_pack_is_clean` 作为回归闸门。

## 5. 安全与隐私

- 不访问网络；不读取材料目录以外的文件。
- 不把 token、密钥写入产物；若材料含密钥，`result.json` 只记录字段名，不复制取值。

## 6. 维护

- 规则阈值集中在 `scripts/pk/`：`firewall.py`（白名单与数字正则）、`coverage.py`（六类矩阵）、`repro.py`（八项清单）、`gaps.py`（套话词表）。
- 新增材料格式时，在 `extract.py` 加一个 `_from_*` 抽取器，并补一条 `tests/run_tests.py` 反例。
